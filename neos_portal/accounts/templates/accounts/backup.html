Backup

Keep a copy of the portal on an external disk. One button brings it up to date.

Update my backup folder

Choose a folder on your external disk once. Each time you click Update, the portal looks at what is already in that folder and saves only what is new or changed, straight into it. Files that were deleted in the portal are moved to a _removed folder, not thrown away. The first time copies everything; after that it takes seconds.

This needs Chrome or Edge on a computer. Safari, Firefox and phones cannot save into a folder. Open the portal in Chrome, or use the zip backups under Advanced below.

Full backup

Everything in one zip: the database, all {{ info.files_count }} uploaded file{{ info.files_count|pluralize }} ({{ info.files_bytes|filesizeformat }}) and the code, with a README that says how to restore. Make one first, and again now and then.

Download full backup

The zip is built as it downloads, so a big one can take a few minutes. Keep this page open until the browser says it has finished. A backup only counts once its download has finished.

Make the changes part of your old backup

Once you have a changes-only file, this command (run on your Mac, in the portal folder) applies it on top of your old backup and writes one updated full backup. New and changed files are put in, deleted files are taken out, and the newest database and code are used. It checks the result before it finishes.

venv/bin/python manage.py merge_backup "OLD-full-backup.zip" "NEW-changes-file.zip" --output "UPDATED-full-backup.zip"

Add more changes files in date order if you have several. Add --replace instead of --output to overwrite the old backup with the updated one, once it has been checked.

Saving it onto an external hard disk

1. Plug in the disk.

2. Make your browser ask where to save: in Chrome, Settings → Downloads → Ask where to save each file before downloading. In Safari, Settings → General → File download location → Ask for each download.

3. Click a download button and choose the disk when the browser asks.

Use one disk for the chain: the portal measures “changes” from the last backup it recorded, whichever disk it went to. To keep a second disk, make a full backup onto it. To restore, start from the last full backup, add each changes-only backup in date order, and use the newest database.json.

Check it afterwards. Open the zip once, or run this on your Mac, which reads every file back and compares the checksums:

venv/bin/python manage.py verify_backup "/Volumes/YourDisk/abc-backup-full-….zip"

The portal runs on a server in the cloud and cannot see your disk, so the browser does the saving. Keep the disk somewhere safe.
